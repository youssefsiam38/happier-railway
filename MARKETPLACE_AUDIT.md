## Identity

- Upstream: https://github.com/happier-dev/happier (about 2,000 stars, active daily, created 2025-12).
- Deployed part: the self-hosted relay server + embedded web app (`happierdev/relay-server`, official, amd64 + arm64).
- Gap: no Railway template named Happier/Happy (catalog snapshot 2026-10-07 and a live gap scan on 2026-10-23).

- Own generic icon; "not affiliated" notice in README and OVERVIEW.
- Verdict: redistributable as a template.

## Security review

| risk | stock relay on a public URL | this template |
|---|---|---|
| open account creation | anyone can create device-key accounts (`AUTH_ANONYMOUS_SIGNUP_ENABLED` defaults to true) | open until the first account, then closed (`SIGNUP_ACCOUNT_LIMIT`, default 1) |
| volume permissions | non-root image cannot write a root-owned Railway volume | start script `chown`s `/data`, drops to `happier` |
| data at rest | E2EE by default (server stores ciphertext) | unchanged |
| token signing secret | auto-generated file on the volume | generated by Railway (`HANDY_MASTER_SECRET`) |
| third-party telemetry | crash reports to upstream Sentry | off unless opted in |
| first-claim race | n/a | documented: claim right after deploy; reset volume if taken |

Alternatives considered: a Caddy basic-auth front door (breaks the native apps and CLI, which cannot send basic
auth); sign-up closed from the start (the deployer could not create an account without two redeploys); generating
the owner's key server-side (puts the E2EE secret next to the data, defeating the encryption). The deployer chose
the auto-lock.
